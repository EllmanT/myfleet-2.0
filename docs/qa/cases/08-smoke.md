# Post-deploy smoke test (15 minutes)

Part of the MyFleet manual QA suite. Conventions, priorities and the pass/fail procedure are in [../README.md](../README.md). Fixtures are in [../TEST_DATA.md](../TEST_DATA.md). Fill the **Result** column with PASS, FAIL, BLOCKED or N/A, and put the defect id in **Notes**. The same cases are in [../qa-tracker.csv](../qa-tracker.csv) for tracking.

Env column: **S** = run on staging/local only (it changes data or time-dependent state); **SP** = safe to run on production with a dedicated QA company.

## SMK: Post-deploy smoke test for the live URL (15 minutes) (20 cases)

Run after every production deploy. Two testers in parallel: Tester A does the browser flows (SMK-001, 004 to 012, 018: about 14 minutes), Tester B does the checks and phone (SMK-002, 003, 013 to 017, 019, 020: about 8 minutes). Use ONLY the dedicated production companies in TEST_DATA section 8 ("QA Smoke Co", "QA Smoke Expired") and the smoke platform account. Every case that creates data deletes it again. Baseline for QA Smoke Co: 3 customers, 2 vehicles (SMK1001, SMK2002), 1 driver with licence and ID uploaded, 1 contractor "Smoke Contractor" (local small 1.00 per km), 3 jobs totalling 100 km and 100.00 revenue, all modules ON, paid up for the next 12 months. STOP and escalate (do not continue) on any failure in SMK-004, 005, 009, 013 or 014. Record the build/commit id in the tracker.
