# Access: sign-up, login, onboarding, roles and permissions

Part of the MyFleet manual QA suite. Conventions, priorities and the pass/fail procedure are in [../README.md](../README.md). Fixtures are in [../TEST_DATA.md](../TEST_DATA.md). Fill the **Result** column with PASS, FAIL, BLOCKED or N/A, and put the defect id in **Notes**. The same cases are in [../qa-tracker.csv](../qa-tracker.csv) for tracking.

Env column: **S** = run on staging/local only (it changes data or time-dependent state); **SP** = safe to run on production with a dedicated QA company.

## AUTH: Sign-up and login (Clerk, plus legacy cookie login) (23 cases)

Production uses Clerk (the SPA is built with REACT_APP_CLERK_PUBLISHABLE_KEY). Cases AUTH-001 to AUTH-015 need a Clerk-enabled build. Cases marked "legacy" need a build WITHOUT the Clerk key (local dev) or the old email/password endpoints called directly; the cookie login still works on the API even when Clerk is on. Never use real customer accounts.

## PRM: Permissions and roles (16 cases)

Roles in the code: Deliverer Admin (Clerk org:admin), Deliverer Manager (Clerk org:member), Super Admin and Site Admin (platform), plus Contractor Manager/Contractor Admin which exist only as role labels. Finance routes (expenses, fuel, quotations, invoices, payments) allow only Deliverer Admin and Super Admin. Expected API status for a refused call is 403. Use the browser Console or curl with the right session to call APIs directly.
