# Plans, billing, users, read-only, deletion, admin console and data export

Part of the MyFleet manual QA suite. Conventions, priorities and the pass/fail procedure are in [../README.md](../README.md). Fixtures are in [../TEST_DATA.md](../TEST_DATA.md). Fill the **Result** column with PASS, FAIL, BLOCKED or N/A, and put the defect id in **Notes**. The same cases are in [../qa-tracker.csv](../qa-tracker.csv) for tracking.

Env column: **S** = run on staging/local only (it changes data or time-dependent state); **SP** = safe to run on production with a dedicated QA company.

## BILL: Trial, plans, billing and reminder emails (25 cases)

Rules from backend/config/plans.js and services/billingEmails.js. Bands: starter 1-2 trucks USD 9, 3 users, 30-day trial; fleet 3-10 trucks USD 29, 10 users, 60-day trial; pro 11-25 trucks USD 59, 25 users, 90-day trial. A NEW sign-up always starts on starter with a 30-day trial. Trial: writable while now is on or before trialEndsAt. Paid: writable until paidUntil plus 7 grace days. Time-dependent cases need a platform admin to set dates with PUT /api/v2/tenant/billing {companyId, trialEndsAt, paidUntil, status, band, extendTrialDays, note} (the Admin console UI only exposes Mark paid, Extend trial 14 days, band, status, paid-until and note). Reminder emails are sent by GET /api/v2/tenant/billing-notices with header Authorization: Bearer <CRON_SECRET> (Vercel cron runs it daily at 06:00 UTC).

## DEL: Company deletion after 30 days (18 cases)

Two ways to schedule: (a) the owner types the company name; (b) automatic, when a billed company has been read-only for 30 days. Both give a 30-day cooling-off (DELETION_GRACE_DAYS, default 30). The purge job runs daily at 02:00 UTC (GET /api/v2/tenant/purge-due). On staging set DELETION_GRACE_DAYS=0 or move dates to speed up. NEVER run a purge against production data.
