# Multi-tenancy isolation, security and file uploads

Part of the MyFleet manual QA suite. Conventions, priorities and the pass/fail procedure are in [../README.md](../README.md). Fixtures are in [../TEST_DATA.md](../TEST_DATA.md). Fill the **Result** column with PASS, FAIL, BLOCKED or N/A, and put the defect id in **Notes**. The same cases are in [../qa-tracker.csv](../qa-tracker.csv) for tracking.

Env column: **S** = run on staging/local only (it changes data or time-dependent state); **SP** = safe to run on production with a dedicated QA company.

## TEN: Multi-tenancy isolation (explicit two-company cross-checks) (31 cases)

The most important suite in the product. Use QA Alpha (ALPHA-ADMIN) and QA Bravo (BRAVO-ADMIN) from TEST_DATA. Every Bravo record has a name that cannot occur in Alpha (suffix "BRAVO-ONLY"), and the ids are written down in the TEST_DATA id sheet. A "foreign id" call must answer exactly like a missing id (HTTP 404 and the same text), so ids cannot be probed. Run each API call from the browser Console while signed in as Alpha, e.g. fetch('/api/v2/vehicle/delete-vehicle/<bravoId>',{method:'DELETE',credentials:'include',headers:{Authorization:'Bearer '+await window.Clerk.session.getToken()}}). Re-run the whole suite after any change to middleware, models or the TENANT_GUARD setting (off, log, enforce).
